# HL/YC 既有 PPO checkpoint 的时间折叠选择设计（预注册）

日期：2026-08-11；本设计在计算 50K/75K 同口径五情景表之前写入。范围严格限制为 HLA `054_00`、YCA `055_00` 的 seed0 既有 25K、50K、75K、100K checkpoint；禁止新训练或改变 reward、观测、动作网格、wrapper、输入 profile 和四基线。

## 时间顺序折叠

- 开发折叠（只用于选择）：2014--2018。
- 时间外测试折叠（只用于报告）：2019--2023。

折叠按验证年份的自然时间顺序固定，不根据产量、天气、压力或任一 checkpoint 结果调整。每个站点使用相同切分。选择只能使用开发折叠；测试折叠在候选确定后才用于报告，不能回头改变候选。

## 同口径证据与输出

对每个 checkpoint，使用对应 054_03/055_03 的五情景回放入口、同一 lowIC root、同一静态四基线和同一 external-auto-N root，生成新而隔离的 `ckpt<step>_prereg_timefold` 输出根。逐年 PPO 终点必须与原 checkpoint validation summary 在 1 kg/ha 容差内一致；management-event 累计 I/N 与季节表 I/N 的差必须为 0。若指标或 provenance 缺失，则写为缺失而非估算。

## 固定候选选择规则

先报告全部四个 checkpoint；只有同时满足以下完整性门槛的 checkpoint 可进入排序：

1. 开发折叠的产量、`WP_ET`、`PFP_N`、I/N 均来自同口径五情景表，且五年逐年终点产量复核通过；
2. 五年均无传输差（I/N 差均为 0）；
3. 开发折叠平均 DAP1 后正管理事件数 >=2，且开发折叠跨年非零动作对签名数 >=2；
4. 开发折叠中至少 3/5 年的 PPO 产量不低于该年其他四情景最大产量减 500 kg/ha（产量稳定性 guardrail）。

在合格候选中，以开发折叠平均 PPO 产量降序选择；若相差不超过 100 kg/ha，依次以开发折叠平均 `WP_ET`、平均 `PFP_N` 降序打破平局。若无候选同时通过，则不选择 PPO checkpoint，站点保留为 PPO 弱势/未证明优势结果。

即使开发折叠产生候选，只有其时间外测试折叠也同时满足第 1--3 条、并且测试折叠平均产量相对其他四情景最大值不低于 -500 kg/ha，才可建议“候选 checkpoint 可进入额外独立 seed/年份验证”；本轮不会直接冻结论文 checkpoint。任何失败均不触发新训练或调参。

## 决策

- HL：25K 是按预注册时间折叠得到的**候选**，而不是可冻结论文 checkpoint。它在产量与 `WP_ET` 上优于 100K，但 PFP-N 明显低于 100K；需独立 seed 或未来年份验证，暂不宣称 PPO 优势，也不启动调参。
- YC：25K 是按预注册时间折叠得到的**候选**，且时间外折叠通过。它不应再被归为“100K 弱 PPO”的代表；但同样只有 seed0，暂不冻结为论文最终结果。下一步是独立 seed/未来年份验证，而非新 100K 训练或调参。

因此，本轮没有任何 checkpoint 获准冻结；HL 和 YC 都保留为“已通过内部时间折叠、待独立验证的 25K 候选”。
