# 028_03 已筛选可优化年份 RL 证据缺口与导师汇报协议

## 1. 任务目标

仅针对历史实验已经筛出的可优化站点—年份，复用已有 DQN、阶段型
MaskablePPO、固定权重同站迁移、四基线、日值表和五情景图。禁止因为文件分散而
重复训练。只有明确缺失的证据才进入后续补做任务。

导师汇报目标是：RL 在产量、`WP_ET`、`PFP_N` 中至少一项严格高于
`null`、`recorded`、`DSSAT auto`、`official expert` 四个情景，同时如实报告另外
两项距离四基线最优值的百分比。导师尚未给出“接近”的数值阈值，因此本任务不
擅自设置 1%、3% 或 5% 容差，也不把“至少一项第一”包装成三项全面胜出。

## 3. Tier 的含义

- Tier A：原始/正式 treatment 或正式单年锚点；
- Tier B：由正式模板与目标年天气构造的派生回放输入；
- Tier 不是优化空间等级。是否可优化必须由独立的 `selection_basis` 字段说明。

## 4. 评价口径

五情景固定为：

1. null；
2. recorded/farmer practice；
3. DSSAT auto；
4. official extension expert；
5. RL（DQN 或阶段型 MaskablePPO，必须标明算法、seed、checkpoint 和训练步数）。

指标固定为：

- 籽粒产量；
- `WP_ET = yield / (10 * ETCP)`；
- `PFP_N = yield / seasonal_N`，其中 `seasonal_N=0` 时为 `not_comparable`；
- 灌溉量、施氮量、生物量、累积奖励；
- 最大/逐日水分与氮胁迫指标；
- 决策时点、请求动作、实际执行动作和预算裁剪情况。

硬报告标签 `advisor_any_metric_strict_winner=true` 仅在至少一个可比指标严格高于
四基线最大值时成立。其余指标只报告绝对差和百分比差，不擅自判定“接近”。

## 5. 防重复执行规则

逐站点—年份登记以下状态：

- 四基线是否完整且为当前输入；
- 已有 RL 算法、seed、checkpoint、模型哈希；
- 是本年训练还是固定权重迁移；
- 终值表、阶段动作表、逐日表、PNG/SVG 是否存在；
- 是否已经按五情景三指标重新评价；
- 是否需要补基线、补冻结评估、补日值/绘图或补训练。

存在可复用模型时禁止重新训练；存在完整 DSSAT snapshot 时禁止重新运行同一情景；
存在正确日值与图时禁止重复绘图。历史 DQN 若受 021_05 探索率调度问题影响，保留
为历史/辅助证据，不冒充当前统一训练框架结果。

## 6. 后续补做顺序

1. 先补四基线和输入 provenance；
2. 再复用冻结模型完成缺失的确定性评估；
3. 再补日值表和既有 027_05 样式的 PNG/SVG；
4. 只有既无可复用模型、又确认有优化空间的年份，才允许按固定阶段型
   MaskablePPO 框架做 seed0 smoke；
5. seed0 工程通过且有目标信号后，才串行补 seed1/2；
6. 不并行启动多站点训练，避免 OOM。

## 7. 图表样式

沿用 027_05 五情景过程图样式，至少包含：

- 降雨与气温；
- 土壤水分/水分胁迫与氮胁迫；
- 灌溉和施肥事件；
- 籽粒产量和地上部生物量；
- 累积奖励；
- 五情景终值指标面板。

逐日 CSV、终值 CSV、动作 CSV、PNG 和 SVG 必须共享同一个来源清单与哈希，防止
图表和数据错配。

## 8. 本任务边界

028_03 第一阶段只做文件与证据审计，不训练、不运行 DSSAT、不改 reward、不改 IC、
不改动作空间。审计完成后生成逐年缺口矩阵，再另立补做任务。
