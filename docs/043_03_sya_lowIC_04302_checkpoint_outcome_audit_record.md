# 043_03 SYA lowIC 043_02 checkpoint 结果审计记录

## 一句话结论

043_02 的天气/预报/归一化输入链路是通的，但没有产生预期的天气响应性。25K、50K、75K、100K 四个 checkpoint 中，没有任何一个同时满足“指标表现可接受”和“措施随年份变化、非模板化”。

因此，043_02 应记录为一次干净的阴性结果：

> 单纯加入天气/完美预报输入和 observation 归一化，不足以让当前 binary-timing MaskablePPO 学会根据不同年份天气调整水氮时机。

## 043_02 做了什么

043_02 在 042_10 binary-timing PPO 基础上加入：

- 当日降雨；
- 当日最低气温；
- 近 7 天累计降雨；
- 未来 7 天累计降雨；
- 未来 7 天平均气温；
- 固定物理尺度 observation 归一化；
- 042_02 已使用过的氮胁迫过程惩罚。

043_02 没有使用 teacher warm-start，所以结果主要反映“天气/预报输入 + 归一化”本身的效果。

## 为什么不能选 50K/75K

50K/75K 虽然比 25K 和 100K 好，但不能作为成功结果冻结，原因有三点：

1. `any_metric_win_four_count = 0`，即没有验证年份在三项指标中至少一项超过四情景最高值。
2. 10 个验证年份动作完全一致，不能回应导师对“天气响应性”的核心质疑。
3. 2014 和 2017 仍出现明显水分胁迫，2022 仍出现较明显氮胁迫，说明固定模板没有稳健解决过程胁迫。

## 对 043_04 的含义

043_02 排除了一个简单假设：

> 只要把天气和完美预报变量加进 observation，PPO 就会自动学会天气响应。

当前证据不支持这个假设。

043_04 不应只是继续加步数，也不应只是筛选 043_02 checkpoint。更合理的下一步是改变训练机制，让 PPO 不仅“看到天气”，还要在训练目标或监督信号中被迫学习“不同天气年份应该有不同措施”。

可能方向包括：

1. 从 lowIC 条件下重新搜索/生成可解释 teacher 轨迹，用行为克隆或 warm-start 给 PPO 一个非模板化起点；
2. 设计天气响应性 reward 或 regularizer，但必须防止 reward hacking；
3. 改训练采样，让干旱年、湿润年、氮胁迫年在训练中更均衡出现；
4. 在 checkpoint 选择中加入天气响应性 guardrail，但它只能筛选，不能单独创造更好策略。
