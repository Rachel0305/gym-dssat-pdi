# 022_07 SY2014 固定网格离线 MC-Q 场景留出泛化测试

## 1. 目的

022_06 发现支持集内部仍存在 Q 排序错位。本任务原计划按完整场景划分 36 个训练场景和12个测试场景，用三 seed 离线 MC-Q 监督检验排序学习能否泛化。

## 2. 预注册硬约束

同一场景不得跨训练集和测试集；每个阶段-动作组合必须在两个集合中都至少出现一次。这一约束用于避免某动作只在训练或测试一侧出现，从而把无覆盖外推误当成泛化能力。

## 3. 可行性检查结果

在任何梯度更新之前统计全数据阶段-动作频数，发现：

| DAP | action | 全部48场景中的样本数 |
|---:|---:|---:|
| 85 | 5（I30/N50） | 1 |

一个样本不可能同时出现在互斥的训练集和测试集。因此原预注册划分不存在可行解。

其他低频动作包括 DAP30/action8 共2条、DAP65/action7和action8各3条；它们理论上可以分到两侧，但会产生极高方差。DAP85/action5 则是严格不可行，而不只是样本少。

## 4. 分支判定

按预注册规则判为 **D：实现/划分失败**。

- DSSAT 调用：0；
- 在线交互：0；
- 梯度更新：0；
- 没有 DQN 泛化结果；
- 不得把本轮写成“离线监督失败”或“DQN学不会”。

## 5. 失败尝试记录

前两次运行在划分搜索阶段超时，均未进入网络训练：

1. `benchmark_results/022_07_failed_attempt_1_single_thread_runtime/`：最初误判为单线程运行慢；
2. `benchmark_results/022_07_failed_attempt_2_split_search_timeout/`：调整线程后仍超时，随后定位到划分约束不可满足。

正式脚本增加了训练前的频数可行性检查，8秒内失败并输出 D 分支，防止再次无效搜索。

## 6. 不能现场修改的内容

本轮不能临时删除 action5、扩大测试集、允许场景泄漏或放宽覆盖条件后继续训练。这些都会改变预注册设计，必须另立任务。

## 7. 推荐的重新设计

下一任务可采用与 target 数值无关的**最小样本支持规则**：

- 预先规定阶段-动作总样本数至少为2，才进入主要留出泛化评价；
- DAP85/action5 标记为 `not_estimable_singleton`，不进入主要排序指标；
- 它仍需在输出中单独报告，不能静默删除；
- 主要动作集合重新做场景级划分和覆盖检查；
- 划分通过后才能启动离线网络更新。

该修改依据样本可识别性，而不是依据动作产量好坏，因此比按结果删动作更可辩护。
