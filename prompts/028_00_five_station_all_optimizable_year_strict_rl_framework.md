# 028_00 五站点全部可优化年份严格强化学习框架总协议

## 1. 最终目标

在 HLA、YC、FQ、LC、SY 五个站点中，对所有满足本协议“可优化年份”定义的站点—年份，使用同一套强化学习代码、算法配置、奖励定义、模型选择协议和评估协议，训练站点—年份本地模型，并争取使 RL 策略的以下三个指标同时严格优于四个对照情景：

1. 籽粒产量（yield）；
2. 水分利用效率（`WP_ET = yield / (10 × ETCP)`，其中 yield 为 kg/ha、ETCP 为 mm，结果单位 kg/m³）；
3. 氮肥偏生产力（`PFP_N = yield / seasonal_N`）。

四个对照情景固定为：`null`、`recorded/farmer`、`DSSAT auto`、`official extension expert`。

算法不预设必须是 DQN 或 PPO。当前首选候选是阶段型 MaskablePPO；若预注册开发集证明其无法形成统一配置，才允许在新任务书中启用已经修正训练协议的 DQN 或其他强化学习算法。确定性搜索只用于判断目标是否客观可达、建立上界和核验 RL 结果，不得冒充强化学习结果。

本协议定义的是一条可执行、可证伪的实验流程，不预先保证所有年份最终一定成功。任何“全部站点全部可优化年份均成功”的结论，必须由冻结配置后的实际结果支持。

## 2. “一套完整强化学习框架”的精确定义

下列内容必须对全部站点—年份冻结一致：

- 算法类别及实现代码；
- 核心超参数；
- 动作含义、预算约束和 action mask 规则；
- 观测字段语义及归一化方法；
- 奖励公式及指标目标构造方法；
- seed 集合与训练预算；
- checkpoint 保存与选择协议；
- 成功判据、输出字段和报告模板。

下列内容属于环境事实，允许按站点—年份变化，不算调参：

- WTH、SOL、MZX、CUL 及 treatment/IC；
- 当年四基线数值；
- 由输入或官方农艺方案确定的物候/决策日期；
- 仅用训练资料拟合并冻结的本地观测 scaler；
- 各站点—年份独立训练得到的模型权重。

因此，“通用框架”不等于五站点共用同一份模型权重，也不等于允许逐年看结果后修改超参数。

## 3. 当前证据边界

截至 2026-07-18，最新阶段型 MaskablePPO 的证据边界为：

- SY：SY2014 训练的三个冻结模型已在 SY2012、2014、2015 做零训练同站跨年验证；这是目前唯一完成的最新 PPO 跨年证据，但旧的 local primary 只比较 auto 与 expert，不能等同于本协议的四情景三指标严格通过。
- HLA：只完成 HLA2010 三 seed；1/3 通过旧 primary，未做最新 PPO 同站跨年验证。
- YC：只完成 YC2014 三 seed；2/3 通过旧 primary，未做最新 PPO 同站跨年验证。
- FQ：只完成 FQ2016 seed0，旧 primary 未通过；未做最新 PPO 同站跨年验证。
- LC：只完成 LC2010 seed0，旧 primary 未通过；未做最新 PPO 同站跨年验证。

历史 DQN 结果受 021_05 已确认的探索率训练协议问题影响，只能作为候选和修复前对照，不能直接充当本协议的正式科学结论。

## 4. 三指标定义与严格通过判据

对每个站点—年份，先由四个基线构造目标：

```text
Y_target   = max(Y_null, Y_recorded, Y_auto, Y_expert)
WP_target  = max(WP_null, WP_recorded, WP_auto, WP_expert)
PFP_target = max(PFP_s for all four baselines where seasonal_N_s > 0)
```

`seasonal_N = 0` 时 `PFP_N` 数学上未定义，必须记为 `not_comparable`，禁止当作 0 或无穷大。若四个基线均无正施氮、无法构造 `PFP_target`，该年份不能进入“三指标严格通过”的正式集合，必须单独报告。

`seasonal_N` 统一使用 DSSAT `Summary.OUT` 中实际执行的季节施氮总量；请求量、管理表名义量和 Summary 实际量不一致时，必须先完成氮记账审计，不能混用分母。RL 灌溉量同理以实际执行量为正式投入，另保留 requested-versus-executed 差值。

为避免 DSSAT 输出舍入误差被误写成科学优势，工程严格通过暂定为：

```text
Y_RL   >= Y_target   + 1.0 kg/ha
WP_RL  >= WP_target  + 0.01 kg/m3
PFP_RL >= PFP_target + 0.1 kg/kg
seasonal_N_RL > 0
```

这三个最小差值只用于数值去重和严格排序；报告中必须同时给出绝对差、百分比差和农学解释，不能把 1 kg/ha 的优势包装成显著增产。

单 seed 同时满足三项才记 `strict_joint_pass=true`。一个站点—年份至少 2/3 seed 通过才记“可复现成功”，3/3 记“稳健成功”。

## 5. “可优化年份”的独立定义

不得用 RL 是否训练成功反向定义年份是否可优化。一个站点—年份只有同时满足以下条件，才进入正式可优化集合：

1. 输入权威或明确标注为经批准的派生天气回放；MZX/WTH/SOL/CUL、treatment、IC、SDATE/PDATE/ICDAT 可追溯；
2. null、recorded、DSSAT auto、official expert 四基线均可运行，三个指标按统一公式可计算；
3. 阶段点、动作空间、预算和 mask 与后续 RL 完全一致；
4. 预注册的确定性可行性搜索至少找到一个满足第 4 节三指标严格判据的管理序列。

第 4 条搜索若未找到，只能标记 `strict_feasibility_not_certified`，不能声称数学上不存在成功策略。输入不权威、基线不完整和派生天气回放必须分层报告，不得混为同一证据等级。

## 6. 防止数据泄漏的三种实验必须分开

### 6.1 同年本地训练与评估

在同一站点—年份训练本地模型，判断统一框架是否具有“逐年可训练性”。允许本地权重不同，但配置不得变。

### 6.2 固定权重同站跨年迁移

冻结训练年模型并直接迁移到同站其他年份；验证年 `learn()` 调用次数必须为 0。该实验回答真正的跨年泛化，不能在验证年重新选 checkpoint。

### 6.3 冻结配置逐年重训

对验证年份使用同一套冻结配置从头训练本地权重，回答框架可移植性。不得根据该年份结果修改配置、奖励或预算。

三者结果分别报告，禁止把“逐年重训成功”写成“固定策略跨年成功”。

## 7. 总体执行阶段

### Phase 0：范围与证据注册表（028_01）

- 列出五站点全部候选年份；
- 区分权威 treatment 年、经批准派生天气回放年、仅有 WTH 年和无效年；
- 列出四基线、旧 DQN、最新 PPO、跨年迁移和 deterministic feasibility 的现有状态；
- 只审计，不训练、不运行大规模 DSSAT。

### Phase 1：四基线与可行性认证

逐年完成输入 provenance、四基线和指标复算。随后使用与 RL 相同的阶段点、动作和预算做预注册的确定性可行性搜索。搜索只读取站点—年份环境，不把测试年 oracle 序列用于调参或训练。

### Phase 2：开发集与测试集冻结

在看到新调参结果前，按站点冻结：

- 开发锚点：HLA2010、YC2014、FQ2016、LC2010、SY2014；
- 同站其他合格年份：优先作为固定权重跨年测试和冻结配置逐年重训测试；
- 派生天气回放年份单列 Tier B，不与权威 treatment 年 Tier A 合并宣称。

若 028_01 发现某锚点输入或严格可行性不成立，必须另立任务书调整开发集，不能现场替换。

### Phase 3：统一奖励和实现单元测试

当前 027 reward 只以 auto/expert 产量门槛触发 bonus，与本协议四情景三指标目标不完全同义，不能直接作为最终 reward 静默沿用。

新 reward 必须：

- 使用四基线构造的三个冻结目标；
- 给出连续的三指标瓶颈 margin，使未过门槛策略也有学习方向；
- 给 joint feasible 策略明确优先级；
- 不因 N=0 产生 NaN、无穷或伪高 NUE；
- 在进入训练前通过边界、排序、量纲、缺失值和 reward 闭合单元测试。

reward 公式一旦进入 Phase 4，不得按站点或年份修改。

### Phase 4：小型全局调参，而非逐年调参

在开发锚点上预注册一个小型候选集合。优先 MaskablePPO；只有预注册分支允许时才加入修正后的 DQN。为节省算力并防止 OOM，严格串行并采用 successive halving：

1. 每个候选先跑 seed0 短预算 smoke；
2. 按预注册排序保留最多 2 个候选；
3. 仅保留候选运行 seed0/1/2 正式预算；
4. 选出唯一全局配置并冻结 config hash。

候选排序使用字典序：

1. 开发年份中 2/3 seed `strict_joint_pass` 的年份数；
2. 所有开发年份的最差三指标归一化 margin；
3. 跨 seed 通过数；
4. 在已可行策略中的总水氮投入；
5. checkpoint 稳定性。

禁止逐年单独扫描参数、根据测试年结果回调配置、无限增加 seed、延长步数救结果或事后挑 checkpoint。

### Phase 5：冻结配置全量验证

唯一配置冻结后，按站点串行执行：

1. 开发锚点正式三 seed；
2. 三个冻结模型同站跨年零训练迁移；
3. 对所有严格可行但迁移失败的年份，用同一冻结配置逐年三 seed 重训；
4. 生成站点—年份—seed 严格通过矩阵。

只有所有 Tier A 可优化年份至少 2/3 seed 通过，才能声称“统一框架覆盖五站点全部权威可优化年份”。Tier B 只单列为派生天气鲁棒性证据。

### Phase 6：日值、图表和汇报

每个正式站点—年份必须输出五情景：null、recorded、DSSAT auto、official expert、RL。必须保存：

- 降雨和气温；
- 土壤水分、水胁迫和氮胁迫；
- 灌溉、施氮及其累计值；
- 生物量、籽粒产量；
- reward 分项及累计 reward；
- yield、ETCP、WP_ET、N、PFP_N；
- CSV、Excel、PNG、SVG、Markdown 和汇总 PPT。

图表必须由同一份冻结日值 CSV 生成，并记录数据与图的 SHA-256 对应关系。

## 8. 硬停止条件

- 输入 provenance 或四基线失败：该年份停止，不改 IC 追求结果；
- 确定性搜索未认证严格可行：不投入大规模 RL，标记未认证；
- 开发集没有任何候选形成统一配置：停止并报告，不在测试年继续调参；
- 冻结配置在测试年失败：如实判定泛化或框架可移植性失败，不回到该测试年调参；
- 不修改现有重要输入、旧训练脚本、旧 reward 和旧结果；新实现采用 adapter/新增模块；
- 全程串行，先 smoke 后正式，禁止并行启动五站点训练，监控内存和 Docker 状态。

## 9. 立即执行顺序

1. 执行 028_01 零训练范围与证据注册表；
2. 根据注册表另立四基线/可行性认证任务；
3. 可行年份集合冻结后，再写 reward 单测和小型全局调参任务；
4. 本任务不直接启动全站点大规模训练。
