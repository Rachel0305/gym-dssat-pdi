# 018_01 五站点 DQN 水氮优化潜力、奖励函数与初始条件审计

日期：2026-07-07

## 0. 本次审计结论先行

当前问题不是“继续训练更多步数”能直接解决的，而是需要先把五个站点分成不同类型：

1. **有明确优化潜力并已出现较好 DQN 结果的站点**：HLA、YC。
2. **有局部优化潜力，但年份敏感或不稳定的站点**：FQ、LC。
3. **有高产响应，但目前不是节水节氮成功的站点**：SY。

因此，当前不能直接声称“五个站点都已满足导师要求”。更稳妥的表述是：

> 五站点均可进入统一 DQN 框架审计，但是否能实现“产量、水氮利用效率同时超过 expert 和 DSSAT auto”是站点年份依赖的。HLA/YC 最接近主成功案例；LC/FQ/SY 仍需分别做优化空间、seed 稳定性、资源效率诊断。

## 1. 导师目标的可操作判定

导师目标：

> DQN 策略尽量同时超过 recorded expert 和 DSSAT auto management 的产量与水氮利用效率。

建议将结果分为四级，避免把“高产”和“节水节氮”混在一起：

| 等级 | 判定标准 | 是否可作为主成功案例 |
|---|---|---|
| 完整成功候选 | DQN 产量 >= expert 和 auto，且灌溉量、施氮量 <= expert 和 auto | 可以 |
| 资源效率成功 | DQN 产量接近最高基线，同时明显节水节氮 | 可以，但措辞要保守 |
| 高产但资源不优 | DQN 产量高，但用水/施氮更多或打满预算 | 不能作为节水节氮成功 |
| 诊断/边界案例 | 站点年份本身优化空间不足，或基线异常 | 只能用于机制讨论 |

## 2. 当前主线奖励函数审计

当前 HLA、YC、FQ、SY、LC 的 baseline-relative DQN 代码大体使用同一类奖励框架：

```text
reward = max(0, GWAD_final - GWAD_null_site_year)
         - 1.0 * irrigation
         - 5.0 * nitrogen
```

证据代码包括：

- `src/run_hla_baseline_relative_dqn_checkpoint_015_12.py`
- `src/run_yc2014_baseline_relative_dqn_015_10.py`
- `src/run_fq2016_baseline_relative_dqn_checkpoint_015_14.py`
- `src/run_sy_local_dqn_train_cross_year_transfer_017_08.py`
- `src/run_lc2010_baseline_relative_dqn_smoke_017_12.py`

### 2.1 这个奖励函数的优点

1. **公式统一**：不同站点使用同一套结构。
2. **本地 baseline 合理**：每个站点年份用自己的 null 产量作为基准，避免把 YC 的产量尺度硬搬到 HLA、FQ、SY、LC。
3. **符合 crop-management RL 常见思想**：收获时给产量收益，过程中扣除水和氮投入成本。
4. **便于解释给导师**：DQN 得分可以粗略理解为“比不管理多出来的产量收益 - 水氮投入成本”。

### 2.2 这个奖励函数的风险

1. `1.0` 和 `5.0` 是当前工程化权重，不是最终经济学标定值。
2. `max(0, ...)` 会让低于 null 的策略不再被产量项继续惩罚，只由水氮成本惩罚。这有利于稳定训练，但也可能让“完全不作为”在某些站点年份得到 0 分，从而吸引 DQN 保守不操作。
3. 对低优化空间年份，DQN 很容易学到“少操作或不操作”，这不是算法失败，而是该站点年份的响应上限低。
4. 对高响应年份，如果 N 成本偏低，DQN 可能打满 N300，形成“高产但不节氮”的结果。

### 2.3 是否需要修改奖励函数参数？

需要考虑，但不建议现在直接凭感觉改。

建议后续只做小规模、统一的敏感性分析：

| 参数方案 | 用途 |
|---|---|
| water_cost = 1, nitrogen_cost = 5 | 当前主线基准 |
| water_cost = 1, nitrogen_cost = 10 | 检查是否减少 N300 打满 |
| water_cost = 1, nitrogen_cost = 20 | 强节氮压力诊断 |

注意：这应作为“统一奖励参数敏感性”，不能变成每个站点单独调一套参数。

## 3. 是否加入氮淋洗惩罚？

建议：**值得审计，但不要马上加入正式训练。**

加入氮淋洗后的奖励函数可写为：

```text
reward = max(0, GWAD_final - GWAD_null_site_year)
         - cW * irrigation
         - cN * nitrogen
         - cL * nitrogen_leaching
```

### 3.1 加入氮淋洗的好处

1. 可以让“节氮”和“环境损失”从口号变成奖励函数中的实际目标。
2. 有助于抑制 DQN 通过打满 N300 换取高产。
3. 更适合回应导师关于水氮利用效率和农业环境意义的问题。

### 3.2 加入前必须完成的核查

| 核查项 | 原因 |
|---|---|
| PDI/gym-DSSAT 是否能稳定提取氮淋洗输出 | 没有可靠变量就不能加 |
| 五个站点是否都有该变量 | 否则跨站点不可比 |
| 变量单位和时间尺度是否清楚 | 避免把日值、季节累计值混用 |
| 导师是否同意把环境损失纳入优化目标 | 这会改变论文目标函数 |

当前结论：氮淋洗项是下一阶段值得做的“奖励函数升级候选”，但不应在没有变量审计前直接进入正式训练。

## 4. 初始条件 IC 审计

### 4.1 可以修改 IC 的情况

可以修改初始条件的合理原因包括：

- MZX 中 IC 设置无效或不一致；
- ICDAT 与 SDATE 冲突；
- 土壤 ID 与 SOIL.SOL 不匹配；
- 作物无法正常生长或初始化异常；
- 品种参数校准时已有证据表明当前 IC 与实测试验不兼容。

### 4.2 不应修改 IC 的情况

不应为了让 DQN 更容易超过 expert/auto 而降低初始水氮。

如果需要测试“较低初始水氮是否增加优化空间”，应作为单独的 IC 敏感性情景，不能和主实验基线混用。

### 4.3 当前站点 IC 状态

| 站点 | 当前判断 |
|---|---|
| HLA | IC=1 后胁迫和管理响应更合理，已成为主线基础之一 |
| YC | 已有较稳定 DQN 结果，暂不优先改 IC |
| FQ | 年份敏感，低优化空间年份不应靠改 IC 强行制造成功 |
| SY | 2014 曾出现 IC=1 后产量异常，后续用 IC=2 修复；需要把 SY IC 作为重点记录项 |
| LC | 017_11 已发现并临时修复土壤 ID、ICDAT/SDATE 等输入链路问题；LC2010 可进入 DQN smoke，但仍需记录输入修复来源 |

## 5. 五站点现有证据审计

### 5.1 HLA

主要证据：

- `DSSAT_auto_validation/HLA_2004/hla2010_to_2015_dqn_transfer_eval_015_17/hla2010_to_2015_transfer_eval_summary.csv`
- `DSSAT_auto_validation/HLA_2004/hla2010_to_2007_dqn_transfer_eval_015_18/hla2010_to_2007_transfer_eval_summary.csv`
- `DSSAT_auto_validation/HLA_2004/hla2010_to_2016_2022_dqn_transfer_eval_015_19/hla2010_to_2016_2022_transfer_eval_summary.csv`

已确认现象：

| 年份 | 主要结果 |
|---|---|
| 2015 | HLA2010 模型迁移到 2015 后，DQN 产量约 7653 kg/ha，接近/略高于 DSSAT auto 7648，且用水低于 auto，不施氮 |
| 2007 | DQN 产量约 7987，高于 recorded 7986 和 auto 7973；seed1 用水 45 mm，seed0 用水 120 mm |
| 2016 | DQN 与 auto 产量同为 7538，但 DQN 用水 60-120 mm，auto 用水 140.8 mm |
| 2022 | DQN 与 auto 产量同为 7935，但 DQN 用水 60-120 mm，auto 用水 143.6 mm |

审计判断：

- HLA 是当前最适合作为“同站点跨年份迁移成功”的主线站点。
- 但 HLA 的优势更多体现为“接近/达到 auto 产量，同时节水、不施氮”，不是所有年份都大幅增产。
- HLA 可以作为主成功案例，但需要强调“资源效率优势”。

## 6. 当前是否需要修改初始条件来增加优化空间？

结论：**不应作为主线手段。**

可以做：

- 对明显输入异常的站点修正 IC/土壤/日期，例如 LC。
- 对 SY 这类 IC 敏感站点保留 IC 诊断记录。
- 对低优化空间站点做 IC 敏感性，作为“情景分析”。

不建议做：

- 为了让 FQ/SY/LC 更容易出现 DQN 优势而人为降低初始水氮。
- 把 IC 敏感性结果和主实验结果混在同一张成功表里。

## 7. 当前是否需要修改奖励函数？

结论：**需要准备，但不是马上大改。**

建议顺序：

1. 先保持当前统一公式，完成五站点“优化空间矩阵”。
2. 对已经出现“高产但打满 N300”的站点年份做小规模 N cost 敏感性。
3. 如果 N cost 提高仍无法解决，再考虑加入氮淋洗惩罚。
4. 所有修改必须在 HLA、YC、FQ、SY、LC 中保持同一逻辑，不能每站点独立调参。

## 8. 下一步建议

### 8.1 立即下一步：生成五站点优化空间矩阵

不训练，只整理：

| 站点 | 年份 | null | expert | auto | DQN 当前最好 | DQN 水 | DQN 氮 | 成功等级 | 下一步 |
|---|---:|---:|---:|---:|---:|---:|---:|---|---|

这个表会直接回答导师最可能问的问题：

- 哪些年份能跑？
- 哪些年份有优化空间？
- 哪些年份 DQN 能赢？
- 赢的是产量，还是水氮效率？
- 哪些站点需要继续优化？

### 8.2 然后做奖励参数敏感性，而不是盲目长训练

优先对象：

| 站点年份 | 原因 |
---|---|
| YC 代表年份 | DQN 产量好，但常用 N300 |
| SY2014 | 高产但资源不优 |
| LC2010 seed1 | 同产量但打满资源，适合诊断 N cost 是否有效 |
| FQ2019 | 高产但 N300，适合检查是否能在少氮下维持优势 |

建议小网格：

```text
water_cost = 1
nitrogen_cost = 5, 10, 20
```

### 8.3 氮淋洗项作为奖励升级候选

先做输出变量审计：

- 是否能从 PDI/DSSAT 输出中稳定提取氮淋洗；
- 是否日值/季节累计一致；
- 是否五站点都有；
- 是否与水氮效率目标一致。

如果成立，再进入：

```text
reward = max(0, yield - null_yield)
         - water_cost * irrigation
         - nitrogen_cost * fertilizer
         - leaching_cost * nitrogen_leaching
```

## 9. 给导师汇报时的安全说法

可以说：

> 我们现在没有直接假设 DQN 一定能在所有站点所有年份都优于 expert 和 DSSAT auto。我们先把五站点分成有优化空间、低优化空间、高产但资源不优、跨 seed 不稳定几类。当前 HLA 和 YC 最接近可写入论文的主结果；LC、FQ、SY 说明不同站点年份的水氮响应差异很大，需要通过统一奖励函数和资源效率约束继续筛选。下一步不是盲目加训练步数，而是做五站点优化空间矩阵、奖励参数敏感性，以及氮淋洗惩罚可行性审计。

不能说：

> 五个站点都已经成功。

也不能说：

> 只要降低初始水氮或者继续训练，DQN 就一定能超过 expert 和 auto。

## 10. 本次审计的底线结论

当前最合理的主线是：

1. **HLA/YC**：作为主要成功与泛化展示站点继续推进。
2. **LC**：作为有潜力但 seed 不稳定的诊断站点。
3. **FQ/SY**：作为站点响应差异和奖励函数敏感性的边界/扩展站点。
4. **奖励函数**：暂保留统一 baseline-relative 结构，但必须准备 N cost 与氮淋洗敏感性。
5. **初始条件**：只因输入合理性调整，不为结果调整。
